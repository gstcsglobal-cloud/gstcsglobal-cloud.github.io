# Claude 를 100배로 쓰는 법 — 나만의 사용 설명서

> 한 줄 요약: **AI 에게 «타자»를 시키지 말고 «일»을 맡긴다. 나는 «무엇이 맞는가»를 정하고, 맞았는지 확인하는 사람이 된다.**

---

## 1. 다섯 가지만 지키면 된다

매번 질문할 때 아래 다섯 개가 들어가 있는지 본다. 하나라도 빠지면 AI 가 «짐작»으로 채운다.

| | 무엇 | 빠지면 생기는 일 |
|---|---|---|
| **① 목표** | 이걸로 무엇을 하려는가 (누가 보나, 어디에 쓰나) | 그럴듯하지만 엉뚱한 방향의 결과 |
| **② 배경** | 지금 상황 · 이미 해 본 것 · 관련 파일·화면 | 이미 버린 방법을 다시 제안함 |
| **③ 완료 기준** | 무엇이 되면 «끝»인가 | 끝없이 고치거나, 반쯤 하고 끝냄 |
| **④ 제약** | 하면 안 되는 것 · 지켜야 할 규칙 · 글자 수 · 말투 | 규칙을 어긴 결과를 다시 고쳐야 함 |
| **⑤ 확인 방법** | 맞았는지 무엇으로 확인하나 | «다 됐습니다»를 믿을 근거가 없음 |

### 나쁜 예 → 좋은 예

- ❌ «차트 좀 예쁘게 해 줘»
- ✅ «글로벌 현황 화면을 **임원 보고용**으로 쓸 거야(①). 지금 왼쪽 칸이 비어 보여(②, 스크린샷 첨부). **1700px 화면에서 세 칸 바닥이 맞으면 끝**(③). 숫자·판정은 바꾸지 마(④). 1700·1920 두 폭에서 스크린샷으로 보여 줘(⑤).»

## 2. 질문 틀 (복사해서 쓴다)

```
[목표] 이걸로 ___ 하려고 해. ___ 가 볼 거야.
[배경] 지금 ___ 상태야. ___ 는 이미 해 봤는데 ___ 해서 안 됐어.
[완료] ___ 이 되면 끝이야.
[제약] ___ 는 건드리지 마. ___ 규칙을 지켜.
[확인] ___ 로 확인해서 보여 줘.
[권한] 판단 필요하면 ___ (물어봐 / 네가 정해 / 추천안 하나만)
```

마지막 줄 **[권한]** 이 속도를 크게 바꾼다.
- «물어봐» — 중요한 결정(숫자의 뜻이 바뀌는 것, 돈, 고객에게 나가는 것)
- «네가 정해» — 디자인 세부, 코드 구조, 문구 다듬기
- «추천안 하나만» — 선택지 나열 대신 결론을 받고 싶을 때

## 3. 일 종류별 틀

### 3-1. 대시보드 기능 추가·변경
```
[무엇] ___ 화면에 ___ 기능을 넣고 싶어.
[왜] ___ 하려고. (예: 매주 임원 보고에서 ___ 를 묻는다)
[범위] 국내만 / 해외만 / 둘 다. 다른 화면은 건드리지 마.
[완료] 검사 통과 + PR + 머지까지. (또는 «PR 까지만»)
```
- **범위(국내/해외)를 꼭 말한다** — 이 대시보드의 제3원칙. 안 말하면 AI 가 «통일»이 좋은 줄 알고 합친다.
- «머지까지»라고 말하면 마지막까지 간다. 안 말하면 중간에 묻는다.

### 3-2. 이상한 숫자·버그 보고
```
[화면] ___ 화면, ___ 카드(스크린샷)
[보이는 것] ___ 라고 나와
[맞는 것] 엑셀에서 세면 ___ 야 (어떻게 셌는지)
[조건] 필터: ___ / 기준일: ___
```
- **«내가 손으로 센 값»을 같이 주면** 원인 찾는 시간이 절반 이하로 준다.
- 「이상하다」만 말하지 말고 «무엇이 얼마여야 하는데 얼마가 나온다»로 말한다.

### 3-3. 문서·보고서·추천서 쓰기
```
[용도] ___ (승진추천서 / 고객 메일 / 임원 보고)
[읽는 사람] ___ (임원 / 고객사 / 팀원)
[분량] ___ 자 / ___ 줄 / 한 장
[말투] ___ (정량 중심 / 정중하게 / 오글거리지 않게)
[예시] 이런 느낌으로: ___ (마음에 드는 예문 1~2개)
[사실 확인] 숫자는 내가 준 것만. 모르면 ○ 로 비워 둬.
```
- **예시 문장 하나가 설명 열 줄보다 낫다.** (예: 이장교 메모처럼)
- «여러 개 써 줘 → 내가 고를게» 는 좋은 방법. 단, 고를 때 **«왜 이게 좋은지»** 한 줄 말해 주면 다음 묶음이 훨씬 맞아진다.

### 3-4. 자료 분석
```
[질문] ___ 가 왜 ___ 한지 알고 싶어
[자료] ___ 표 / ___ 기간 / ___ 운영단위
[기준] 국내/해외 규칙 · 내적만 · 발생일 기준 등
[결과물] 표 / 차트 / 한 줄 결론 / 엑셀
[주의] 추정은 추정이라고 적어
```

### 3-5. 기술 과제·아이디어 검토
```
[문제] ___ (현장 증상 그대로)
[이미 아는 것] ___ (예: 로그에는 이상이 없다)
[원하는 것] 아이디어 ___ 개 / 실현 가능성 순으로 / 비용 대략
[버릴 기준] ___ 한 것은 빼 줘
```
- 「이미 아는 것」을 먼저 주면 쓸모없는 제안이 줄어든다. (예: «로그 이상 없이 꺼진다» → 로그 분석 아이디어 제외)

## 4. 맡기는 크기를 키우는 법 (이게 10배 → 100배의 차이)

**맡길 수 있는 크기 = 검증할 수 있는 크기**다. 그래서 아래 셋을 쌓아 두면 점점 더 큰 일을 한 번에 맡길 수 있다.

1. **규칙을 문서에 남긴다 — CLAUDE.md**
   - AI 가 한 번 틀린 것, 내가 한 번 정한 것은 **«CLAUDE.md 에 적어 둬»** 라고 말한다.
   - 다음 세션의 AI 는 그 문서를 읽고 시작한다. 같은 설명을 두 번 하지 않게 된다.
2. **검사를 먼저 만든다**
   - «이 기능 만들 때 **틀리면 붉게 뜨는 검사**도 같이 만들어 줘.»
   - «일부러 틀리게 만들어서 검사가 잡는지도 확인해 줘(음성 대조).»
3. **확인 결과를 «눈으로» 받는다**
   - 「됐습니다」 대신 **스크린샷 · 숫자 대조표 · 검사 결과**를 달라고 한다.

---

## 5. 시간을 더 줄이는 습관

- **한 번에 여러 개를 맡긴다** — «A, B, C 다 하고 PR 하나로 머지까지». 하나 끝날 때마다 기다리지 않는다.
- **세션을 나눠 동시에 돌린다** — 대시보드 작업 세션 / 문서 작성 세션 / 아이디어 세션을 따로. 서로 맥락이 섞이지 않는다.
- **결정은 모아서 한 번에** — AI 가 물어볼 것이 여러 개면 «결정할 것만 목록으로 정리해 줘» 하고 한꺼번에 답한다.
- **스크린샷은 최고의 설명** — 화면 문제는 말보다 캡처 한 장 + «여기 빨간 부분» 이 빠르다.
- **「알아서 해 줘」의 범위를 정한다** — «디자인은 알아서, 숫자는 물어봐» 처럼 반만 맡기는 것도 좋다.

## 6. 자주 쓰는 한 줄 주문

| 하고 싶은 것 | 이렇게 말한다 |
|---|---|
| 끝까지 맡기기 | «검사 통과하면 PR 올려서 머지까지 하고 알려 줘» |
| 결론만 받기 | «선택지 말고 네 추천 하나만, 이유 한 줄» |
| 규칙 남기기 | «이거 다음에도 지켜야 하니까 CLAUDE.md 에 적어 둬» |
| 과장 막기 | «확인 안 된 건 ⚠ 표시하고, 숫자는 지어내지 마» |
| 검증 받기 | «스크린샷이랑 숫자 대조표로 보여 줘» |
| 방향 먼저 보기 | «만들기 전에 시안 먼저 보여 줘» |
| 다른 관점 | «반대 입장에서 이 계획의 약점 세 개만» |
| 여러 안 받기 | «말투 다르게 30개, 내가 고를게» |
| 정리 받기 | «지금까지 정한 것만 한 장으로 요약해 줘» |

---

## 7. 피해야 할 것

- **«알아서 잘»만 말하기** — AI 는 «잘»을 모른다. 누가 보고 무엇에 쓰는지를 말한다.
- **숫자를 AI 에게 만들게 하기** — 성과·보고 숫자는 내가 준다. 모르면 «○ 로 비워 둬».
- **중간에 방향만 바꾸고 이유를 안 말하기** — 이유를 말해야 다음에도 같은 판단을 한다. 그리고 그 이유를 CLAUDE.md 에 남기라고 한다.
- **결과를 확인 없이 쓰기** — 특히 고객·임원에게 나가는 것은 숫자 하나라도 직접 본다.
- **한 세션에 모든 걸 섞기** — 대화가 너무 길어지면 앞의 맥락이 요약되며 흐려진다. 주제가 바뀌면 새 세션을 연다.

- [ ] 무엇이 되면 끝인지 말했나?
- [ ] 건드리면 안 되는 것을 말했나?
- [ ] 무엇으로 확인할지 말했나?
- [ ] 어디까지 AI 가 정해도 되는지 말했나?
