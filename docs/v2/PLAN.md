## 사용자가 정한 것 (2026-10-10)

- **목표 숫자는 화면에서 고친다** — 하드코딩하지 않는다(`/targets/` · 판정 기준까지 같은 화면 · `ops_params`).
- **어느 차트를 남길지는 Claude 판단에 맡긴다**(4절 판정표 — 2차에서 페이지마다 확정한다).
- **알림은 제안 그대로** — 카카오 챗봇 「브리핑」부터(6절 ①).
- **낱말** — 「14일 안 재고장」 같은 말을 쓰지 않는다. 「14일 이내 재고장」 · 「기한 경과 건」 · 「이번 주 확인 사항」처럼 보고서 한국어로.
- **화면의 설명문은 걷어낸다** — 경영진·고객에게 보이는 화면에 «기준 … (자료의 마지막 날) · W41 (10-04~)» 같은 근거·정의 문구를
  두지 않는다. 날짜는 «2026-10-08 기준»만. 근거는 관리자의 「설명 표시」를 켰을 때만 보이고, 숫자의 뜻이 바뀌는 경고는 ⚠ 하나로 남긴다.
- **오프라인 판은 마지막에** — 개선이 끝나 확정된 뒤 고친다.

## 지킬 것 (2단계 전체에 걸린다)

- **주간현황(report · report-kr)은 손대지 않는다**(사용자 지시 — 보고서 작성용).
- **숫자는 한 자리도 안 움직인다.** 2단계는 «무엇을 어디에 보이나»를 바꾸는 일이다.
  판정(GST.EQ · GST.PM · GST.ops.bm · GST.riskRank · GST.WARR)은 그대로 부른다. 새 지표도 그 행들을 «정해진 창으로 나눈 비율»일 뿐이다.
- **해외 기준은 건드리지 않는다**(제3원칙). 국내 전용 분기도 그대로 둔다.
- **차트를 지우기 전에 사용자 확인을 받는다.** 아래 판정표는 «제안»이다 — 현장에서 실제로 보는 차트가 있을 수 있다.

### 운영 목표 (`/targets/`)

- 지표 × 범위마다 목표 하나. 화면은 **가장 좁은 목표**를 쓴다: 운영단위 > 구분(국내/해외) > 전사.
- 주의 경계(warn)를 비우면 지표의 기본 띠(`GST.METRICS[].band`)를 쓴다 — 가동률 ±3p · PM 비율 ±10p · 100대당 고장 ±15% · 개수 지표 ±2.
- 쓰기는 **관리자 + 쓰기 권한**만(서버 `_tgt_who`). 사이트 담당자(editor)도 못 바꾼다 — 목표를 바꾸면 모든 화면의 판정 색이 바뀐다(기준 정보와 같은 무게).
- 남의 변경을 덮지 않는다(`p_at` = 읽은 `updated_at`). 지우지 않고 감춘다. 이력이 남는다.

## 2. KPI 카드 규격

**네 줄의 자리가 언제나 같다** — ① 이름(+ 창) ② 값·단위(+ 작은 추이) ③ 목표 막대 ④ 목표 문장 ⑤ 직전 대비 · 분모.

```
● 설비 100대당 고장                 최근 4주
46.00                               ╱
▬▬▬▬▬▬▬▬▬▬▬▬▬▬|▬▬▬▬               ← 목표 자리에 눈금
목표 30.00 이하 · 초과 16.00        ← 없으면 «목표 미설정»(자리는 남는다)
▲ +30.00 직전 4주 대비 · 반입 50대
```

- 색은 판정(정상·주의·위험)이 정한다. 목표가 없으면 회색(판정 없음) — **목표 없이 빨갛게 칠하지 않는다**.
- 목표 없는 «개수» 지표(재고장 대수·처리함 건수)는 막대를 채우지 않는다 — 끝값이 없으면 길이에 뜻이 없다.
- 누르면 카드가 «센 그 배열»이 팝업 목록이 된다(v133 규약). 비율 카드는 분자·분모를 팝업 머리에 적는다.
- 지금 여덟 페이지의 KPI 카드(56장)는 페이지마다 줄 구성이 다르다. 화면을 옮길 때 이 카드로 바꾼다 — 목표가 걸리는 카드부터.

## 3. 탭 구성 — 12개 → 8개 + 머리 메뉴

**원본 시트 이름이 아니라 «질문»으로 나눈다.** 지금은 수선실적 → 고장분석, 자재실적 → 자재처럼 시트를 따라 갈라져 있어
「F16 이번 달 왜 고장이 많지」의 답이 관제 · 사이트 상세 · 고장분석 세 탭에 흩어져 있다.

| 새 탭 | 지금의 무엇 | 비고 |
|---|---|---|
| **내 화면** | 새 `/home/` | 셸 첫 탭 |
| **관제** | 통합 관제 + 사이트 상세 | 사이트 상세는 관제에서 운영단위를 고르면 아래로 펼쳐진다(별도 탭이 아니다). 주소 `/site/` 는 남긴다 |
| **주간 현황** | 그대로 | 손대지 않는다 |
| **고장** | 고장분석 | 차트 32 → 14 안팎 |
| **정비** | PM 점검 + CIP 현황 | 둘 다 «계획된 작업을 제때 했나» — 섹션 탭으로 |
| **설비** | 설치현황 | |
| **자재·비용** | 자재실적 + TCO | TCO 는 자재 위에서 돈다 |
| **인원** | 인원현황 + 흩어진 «공수» 차트 | 공수(분자 실적 · 분모 인원)는 지금 고장·PM 두 곳에 따로 있다 |

머리(셸 툴바) — **처리함**은 배지(열린 일 수)로, **분석 작업대 · 운영 목표 · 데이터 관리**는 ⚙ 메뉴로. 처리함은 누구나, 작업대·목표·데이터는 등급을 따른다.

**v178 실제 적용 — 「내 화면(홈)」을 글로벌 현황에 합쳤다(사용자 확정 · 탭 7개).** 두 화면이 같은 KPI·같은 확인 사항을 다른 모양으로 보여 줬다.
글로벌 현황(`/hub/`)이 첫 탭이고 «보기»(전사 요약 · 운영 관리 · 사이트별)로 옛 홈의 세 화면을 고른다. `/home/` 은 `/hub/` 로 넘기는 안내 페이지,
셸은 `TAB_ALIAS{home:'hub'}` 로 옛 id 를 읽는다. 자세한 규약은 CLAUDE.md 「디자인 3.0」 절.

⚠ 탭 id 를 바꾸면 딥링크(`#tab=fault`)·자동순회 저장값·챗봇 출처가 깨진다. **id 는 그대로 두고 이름표와 순서만** 바꾼다. 합친 탭(정비·자재·비용)은 처음엔 «안쪽 섹션 탭»으로 두 페이지를 그대로 띄운다 — 페이지를 합치는 일은 그다음이다.

## 4. 차트 판정표 (설계 당시 제안 — 실제 적용은 이 절 끝 «v174 실제 적용»)

판정 네 가지:
- **남김** — 고유한 질문에 답하거나 목표와 견줄 수 있다
- **합침** — 같은 모양(축만 다른 건수 막대)을 «축 선택» 차트 하나로
- **접음** — 기본은 접힌 «상세» 섹션. 입력률 30% 미만 열(알람유형 0.3% · 현상/원인 ~10%)은 **자동으로 접힌다**(`GST.FILL_MIN` 기준 그대로 — 30% 를 넘으면 저절로 펼쳐진다)
- **옮김 / 뺌** — 다른 탭과 중복이거나 KPI 카드와 같은 것

### «축 선택» 차트 — 합침의 부품

지금 같은 모양의 «축만 다른 건수 막대»가 고장·자재·설비·PM·CIP 에 스물 개 가깝다. 부품 하나로 바꾼다:

```js
GST.axisChart(canvas, { rows: ()=>배열, axes:[{k:'line', label, get:x=>x.line}, …], value:x=>1, top:15, drill:true })
```

- 카드 머리에 축 선택(세그먼트) — 고른 축은 그 카드에 기억한다.
- 상위 N 밖은 «그 밖»으로 담는다(버리지 않는다 · v122).
- 막대를 누르면 그 행들(`$rows` 규약 · v83) — 지금 차트 클릭이 거는 필터 토글은 축마다 그대로 이어 준다(`GST.filters.toggle`).
- ⚠ 축마다 필터 키가 있는 것(LINE·모델)과 없는 것(Tool Maker)이 섞인다 — 없는 축은 드릴만 하고 필터를 걸지 않는다.

### v174 실제 적용 — 제안과 다른 자리

카드 **97 → 66**(고장 32→19 · 자재 15→11 · PM 11→8 · 설비 14→9 · TCO 5→4 · CIP 10→7 · 인원 10→8).

- **«합침»은 새 부품(`GST.axisChart`)이 아니라 배치 층(`GST.chartLayout`)으로 했다.** 같은 질문의 카드를 한 자리에 모아 «기준»
  단추로 하나만 보인다. 카드마다 이미 붙은 드릴·필터 토글·제외 검색·내보내기를 새 부품으로 옮기면 카드마다 조용히 갈린다 —
  이번 단계는 숫자를 한 자리도 안 움직이는 것이 조건이었다. 부품은 필요해지면 그때(지금은 «축 선택» 카드가 설비 현황 하나뿐이다).
- **«뺌»은 숨김이다**(`data-gst-retired`) — 코드·DOM 은 남고 spec 한 줄로 되돌린다. PPT 전체 내보내기도 보이는 것만 담는다.
- 고장 — 「어디서」(설비·LINE·모델·공정) · 「왜」(현상·원인·조치·알람 — 정합성 표 옆) · 「모델별 MTBF/FTFR」 · 「TBM 사후 재고장(작업자·LINE·경과일)」 네 묶음.
  뺀 것 다섯(유상 vs 무상 · 의뢰유형 · 작업시간 분포 · 투입 인원수 · 이상 집중 설비 TOP) 그대로. **«옮김 → 인원 공수»는 안 했다** —
  인원 화면이 수선실적을 안 읽으므로 배치가 아니라 자료 일이다. 원인 차트 «자동 접음»도 다음으로(지금은 한 카드로 묶었다).
- 자재 — 「어디서」(설비·모델·공정·LINE)는 설비·공정 섹션의 설비 상세 드릴 바로 위 · 「사유」(교체사유·무상사유). 유상 vs 무상만 뺐다.
  **자재별 교체 TOP 은 남겼다**(제안은 파레토로 합침) — 「제외 검색」(O-RING 44% 를 빼고 보기)이 붙어 있어 파레토가 대신 못 한다.
- 설비 — 누적 반입·가동은 **한 차트 두 선**(제안 그대로 · 그림을 바꾼 유일한 자리). 모델·고객사·Tool Maker 단독 차트는 숨김(개요의 축 선택
  카드가 같은 분포) · 연도별 Turn On 숨김. 날짜 미기재 표는 «데이터 관리로 옮김» 대신 **관리자에게만**(사실은 품질 팝업이 모두에게).
  워런티 두 카드 합치기는 다음.
- PM — 상태 분포 숨김 · 「지연이 어디에」(LINE·모델) · 「앞으로」(60일 예정·8주 공수). 점검 공수의 인원 화면 이동은 위와 같은 이유로 다음.
- CIP — 진행 추이(누계)·구간별 신규를 한 자리(막대+누계선 한 차트는 다음) · 층·구역·모델·반입 연도 한 자리. 공정별은 히트맵 옆 그대로.
  잔여 TOP·항목별·항목 요약 표 합치기는 다음.
- 인원 — 사이트·직무 한 자리 · 과정별 이수·단계 퍼널 한 자리. **본사 Lv.2 대상 판정을 `l2Tgt` 하나로**(국내 전원 · 해외 6개월+) —
  카드·막대·PPT 셋이 국내까지 6개월을 세고 있었다.

- 토큰은 theme.css 한 벌(v139)이 이미 있다. 새 토큰을 만들지 않는다.

  페이지 인라인 규칙을 지우는 일(위 순서)은 그대로 남아 있다 — 이번에는 공통 층이 페이지 규칙을 «이기게» 했을 뿐이다.
