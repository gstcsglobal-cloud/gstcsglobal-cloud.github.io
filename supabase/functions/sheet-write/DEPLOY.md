# sheet-write 재배포 — 교육 시트 쓰기 복구 + 비고 열 시프트 수정

보내주신 **현재 배포본 기준**으로 gid `"0"`(교육현황) 스키마 세 줄만 고쳤습니다.
다른 탭(인원명단·휴가·실적)과 인증·잠금·지문 검증 로직은 **한 글자도 건드리지 않았습니다.**

## 무엇이 문제였나

### ① 지금 이미 고장 — 교육 시트 저장이 전부 실패 중
```ts
headerHint: [(h) => h === "교육과정", (h) => h === "인원"],
```
시트 B열 머리글이 `교육과정` → `Site`로 바뀌고 8열이 `법인 교육과정`이 되면서
정확일치가 깨져 `NO_HEADER` 예외가 납니다. 그 결과 교육현황 탭의
`update / append / delete / row / fresh`가 **전부 실패**합니다.
인원명단에는 `cascadeTo:"0"`이 걸려 있어 인원 편집의 교육 캐스케이드도 같이 막힙니다.

→ 머리글이 바뀌어도 버티도록 부분일치로 교체했습니다(구·신 레이아웃 양쪽 동작).

### ② 헤더를 고치는 순간 터질 지뢰 — 비고 열이 밀려 있었음
```ts
note: { col: 16, max: 200 },   // 16은 이제 Scrubber Lv.2 완료일
```
대시보드는 실제로 `note`를 보냅니다(비고 입력칸 + 퇴사일 자동기록 체크박스).
①만 고치고 배포했다면 **비고를 저장하는 순간 Lv.2 완료일이 지워졌을 겁니다.**
지금까지 데이터가 무사한 건 ① 때문에 쓰기 자체가 막혀 있었던 덕입니다.

→ `note.col` **16 → 18**. 더불어 신설된 두 열을 스키마에 명시했습니다:
`lv2date(16)` · `lv3date(17)`. 지금 대시보드 UI엔 입력칸이 없지만, 열을 등록해 두면
나중에 편집 기능을 붙일 때 위치를 다시 추측하지 않아도 됩니다.

## 실제 시트로 검증한 결과

| 확인 항목 | 결과 |
|---|---|
| 헤더 행 탐지 | 0행에서 찾음 (수정 전 `NO_HEADER`) |
| 18열 머리글 | `비고` ✓ |
| 16 / 17열 소제목 | `Scrubber Lv.2` / `Scrubber Lv.3` ✓ |
| 데이터 시작 행 | 3행 (`dataOffset:3` 그대로 유효) |
| 비고 저장 시뮬레이션 | 18열만 기록, 16·17열 완료일 보존 ✓ |

수정 전 동작이었다면 어떤 인원의 비고를 저장하는 순간
Lv.2 완료일 `2026-06-01`이 `퇴사일: …`로 덮어써졌습니다.

## 배포 방법

1. Supabase → Edge Functions → **sheet-write** 열기 (새로 만들지 않습니다)
2. `index.ts` 내용을 이 폴더의 `index.ts`로 전체 교체
3. **Deploy**

Secret 변경 없음 (`GS_SA_EMAIL` · `GS_SA_KEY` 등 그대로).

## 배포 후 확인

1. 대시보드 인원현황 → 아무 인원 클릭 → 편집창이 뜨고 **교육 항목이 채워져 보이는지**
   (지금은 교육 시트를 못 읽어 비어 있거나 오류가 납니다)
2. 비고에 아무 글자나 넣고 저장 → 구글시트에서 **S열(비고)만 바뀌고
   Q열(Scrubber Lv.2 완료일)이 그대로인지** 눈으로 확인

이 두 가지가 통과하면 교육 시트 편집이 완전히 복구된 것입니다.
